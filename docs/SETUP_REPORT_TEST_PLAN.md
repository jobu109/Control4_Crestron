# Readable setup report: first checkpoint

Revision `Stage1-CP10a-SetupReport`. Adds gateway Export_Setup_Report input and Setup_Report_File$/Setup_JSON_File$ outputs. The four parameters, leading skips and signal-type separator remain unchanged. No startup request or device command is added.

1. Update the Gateway symbol, inspect wiring, compile/load the program for **4-Series only**, and Connect.
2. Pulse Export_Setup_Report once. Busy_FB and Diagnostic$ report work/progress. It reads the existing inventory/category endpoints and the Python-verified GET /api/v1/agents/ui_configuration using shared authentication.
3. On completion, file outputs identify `/user/Control4Gateway_1_setup.txt` and `/user/Control4Gateway_1_setup.json` (Gateway_ID determines the number). Inventory_File$ also updates: the same report is embedded under setup_report in the inventory JSON for the already-running collector.
4. Say exported. The current SFTP window can continue without another password; the assistant can run tools/Expand-SetupReport.ps1 on the automatically downloaded inventory to produce the local readable TXT and JSON. Updated collector code does this automatically on future launches; an already-running collector does not reload its script. No restart is required for the embedded inventory route.
5. Open the TXT and inspect Living Room Watch/Listen names and Source_ID$ values, configured Audio/Video parameter values, category candidates and inventory names. Check another room's source lists. Confirm unknown mappings are labeled unresolved rather than inheriting Living Room values. The JSON holds the same structured information and readable_text.

This is a **partial discovery checkpoint**, not completion of automatic installer configuration. Endpoint/output values are copied from current program registrations and labeled configured_in_program_not_automatically_verified. They are not hardcoded Living Room defaults and do not establish the right mapping for an unconfigured installation. Rooms advertised by Watch/Listen discovery without a registration remain unresolved. The report does not mistake a source ID for an audio endpoint or a matrix input ID for a selected source.

Inventory metadata can lack room membership or device function. Light category proxy entries have candidate Light parameters; category membership alone is not proof of a usable device. Other items are listed by friendly name and type with unresolved function, including unclassified shades. No guessed shade parameters or automatic matrix output assignments are supplied. Current guided capture remains Living Room-specific; configurable multiroom identification and validated relationship discovery are still required to satisfy the full installer requirement.

Only selected room/source metadata, sanitized inventory names/types/IDs and configured parameters are exported. Tokens, credentials, arbitrary UI fields and media/account payloads are excluded. Unknown schemas, skipped entries and partial request failures are explicit. JSON and TXT are written through temporary files; the completion event follows both reports and the inventory mirror. Failure diagnostics use exception types, not raw payloads.

Local validation: Release build passed (existing generated CS0162 warning), setup parser/privacy/large-ID/shape/deduplication/partial-failure and existing inventory/Audio/Video/capture/socket/shade checks passed. All seven wrappers compiled series4 with zero errors/warnings. RMC4 export/schema correctness and usefulness of the resulting report await testing.
