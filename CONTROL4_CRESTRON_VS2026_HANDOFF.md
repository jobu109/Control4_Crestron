## What the gateway source currently does

- `GatewayRegistry.Get(ushort)` creates/shares one `GatewayCore` per `Gateway_ID`.
- `Control4_Gateway.Initialize(gatewayId, ipAddress)` wires events and configures host; no network activity in the constructor or SIMPL+ `Main()`.
- Authentication uses only the account parameters in SIMPL Windows; `Main()` forwards them after initialization. The manual token input and public token setters have been removed.
- `GatewayCore.SetAccountCredentials(username, password)` accepts account credentials in memory. `Authenticate()` makes the three Control4 cloud calls on a queued worker to obtain a Director token. `Connect()` obtains one automatically if needed, then attempts the local `/api/v1/items` request. Token renewal occurs on the next request after its reported lifetime approaches expiry; no background renewal timer is used. **The new auth build has not yet been tested on the RMC4.**
- No manual token entry is supported. The gateway acquires and renews Director tokens internally.
- The auth request currently uses the public application key and client identity from [pyControl4's published account flow](https://github.com/lawtancool/pyControl4/blob/master/pyControl4/account.py), which was previously used successfully in the Python test. Control4 [provisions application keys per application](https://developer.control4.com/assets/static/oauth2.html); this compatibility dependency should be replaced with a dedicated key for a long-term deployment.
- It uses synchronous `HttpWebRequest` inside queued work for REST operations. Local REST requests now validate the exact SHA-256 certificate fingerprint observed at EA-5 IP `192.168.1.160` on 2026-11-13. The override is set on each local request; cloud requests keep normal certificate validation. The certificate pin must be updated when the EA-5 certificate rotates. This code is locally built but not yet RMC4 verified.
- `Control4_Light` exposes `On`, `Off`, `SetLevel`, `Query` and feedback event through shared `GatewayCore`. These are **not yet end-to-end verified on RMC4** against Control4 REST or live feedback.
- `QueryLight` retrieves a response but intentionally does **not parse it or update light feedback**. `Valid_FB` and `Level_FB` therefore cannot be treated as live device state in this baseline. The current build emits `Busy_FB` at queue start and completion; its processor behavior has not yet been verified.
- `Control4_Shade`, `Control4_Audio`, `Control4_Video`, `Control4_Generic` are **initialization-only placeholders**. The corresponding SIMPL+ wrappers expose `Initialized_FB` when `Initialize` returns, not device online state.
- WebSocket / Socket.IO live event handling, robust reconnection, initial synchronization, and most device operations **remain unimplemented**. Token renewal is implemented on demand but awaits processor validation.
